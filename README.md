# sasa

영재원에서 반에 있는 천재 둘 납치해서 만든 리듬게임

## 실행

```bash
pip install -r requirements.txt
python app.py              # 곡 선택 화면
python app.py R.dx         # 이 채보로 바로 시작
```

곡 선택 화면에서 `↑` `↓` 로 고르고 `ENTER` 로 시작, `ESC` 로 종료.
플레이 중 `ESC` 를 누르면 곡 선택으로 돌아온다. 노트 키는 `Z` `X` `.` `/` 네 개.

곡이 끝나면 결과 화면에서 판정별 개수와 정확도, 그리고 내 입력 오차를 바탕으로
계산한 추천 `offset` 값을 보여준다. 노트가 계속 이르게 느껴지면 그 값을 채보의
`offset:` 에 적으면 된다.

## 채보가 노래랑 안 맞을 때

두 가지가 전혀 다른 문제라서 먼저 구분해야 한다.

**① 처음부터 끝까지 일정하게 밀림** → `offset:` 으로 고친다.
곡을 한 번 플레이하면 결과 화면이 추천 값을 알려준다.

**② 처음엔 맞다가 뒤로 갈수록 벌어짐** → `offset:` 으로는 절대 못 고친다.
채보와 노래가 **서로 다른 속도로 흐르는** 거고, 원인은 거의 항상 믹서 샘플레이트다.

### 왜 벌어지나

SDL 믹서는 열려 있는 레이트와 다른 음원을 전부 리샘플하는데, 이 리샘플러가
**길이를 보존하지 않는다.** 이 저장소의 음원으로 실측한 값:

| 음원 원본 | 믹서 | 디코드 길이 | 오차 |
|---|---|---|---|
| 48000 Hz | 44100 Hz | 146.666 s | **-0.129%** (곡 끝 -190 ms) |
| 48000 Hz | 22050 Hz | 146.798 s | -0.040% |
| 48000 Hz | **48000 Hz** | 146.856 s | **0.000%** |

`R.mp3` 는 48 kHz인데 믹서는 44.1 kHz로 열려 있었다. 2분 26초짜리 곡이 190 ms
짧아지고, 판정 창이 ±40 ms니까 후반부는 통째로 빗나간다.

**레이트를 음원에 맞추면 오차가 정확히 0이 된다.** 리샘플러가 아예 끼지 않기 때문.

### 어떻게 처리되나

`make_chart.py` 는 음원의 원본 레이트로 믹서를 열어 분석하고, 그 값을 채보의
`sample_rate:` 에 적어둔다. `app.py` 는 곡을 시작하기 전에 그 레이트로 믹서를
다시 연다. 채보를 만든 타임라인과 재생 타임라인이 같아지므로 밀릴 수가 없다.

`sample_rate:` 는 "음원의 레이트"가 아니라 **"이 채보의 시간이 측정된 기준"** 이다.
그래서 예전에 44100 믹서로 만든 채보는 `sample_rate: 44100` 으로 남겨둬야 그대로
맞는다 — 원본 48000으로 바꾸면 오히려 새로 밀린다. (`R.dx`, `pixelation.dx` 가
이 경우라 44100으로 표기해 두었다.)

### 확인 도구

```bash
python check_sync.py R.dx
```

채보를 재생하지 않고 음원의 온셋 위에 노트가 얼마나 잘 얹히는지 점수를 내서,
상수 밀림(shift)과 배속 어긋남(scale)을 분리해 보여준다. `scale` 이 1.00000이면
속도는 맞는 것이고, 1.00125처럼 나오면 그 믹서 레이트가 틀린 것이다.

탐색 범위를 **1/4박 이내로 제한**한다. 음악은 주기적이라 반박자씩 밀어도 온셋에는
똑같이 잘 맞아서, 그보다 큰 보정값은 싱크 교정이 아니라 리듬을 바꾸는 것이 된다.

같이 나오는 **shift 신뢰구간**은 점수가 최고점의 90% 이상으로 유지되는 범위다.
좁으면(수 ms) 그 offset을 믿어도 되고, 넓으면(수십 ms) 곡의 온셋이 뭉툭해서
추정이 약한 것이니 직접 플레이해서 결과 화면 값과 대조하는 편이 낫다.


## .dx — 채보 포맷

`app.py` 는 실행 파일과 같은 폴더의 `.dx` 파일을 전부 찾아 목록에 올린다.
`.dx` 는 UTF-8 텍스트고 헤더와 노트 두 부분으로 나뉜다.

```
title: Pixelation
artist: Sound Souler
audio: pixelation.mp3
bpm: 129.2
offset: 0
lead_in: 2000
difficulty: NORMAL
level: 6
beats_per_measure: 4

[notes]
# when      lanes   hold
2116        1
4:1         2,4
4:1.5       3       1b
```

### 헤더

| 키 | 뜻 | 기본값 |
|---|---|---|
| `title` | 곡 선택 화면에 뜨는 이름 | 파일 이름 |
| `artist` | 아티스트 | 없음 |
| `audio` | 음원 파일. 채보 파일 기준 상대 경로 | 없음 (무음 플레이) |
| `bpm` | 템포. `measure:beat` 표기를 쓰려면 필수 | 120 |
| `sample_rate` | 이 채보를 만들 때 쓴 믹서 레이트 Hz. 아래 참고 | 음원에서 자동 판독 |
| `offset` | 판정 보정 ms. 노트가 늦게 오면 올린다 | 0 |
| `lead_in` | 첫 노트 전 무음 구간 ms | 2000 |
| `difficulty` | `EASY` / `NORMAL` / `HARD` 같은 라벨 | 없음 |
| `level` | 난이도 숫자. 0이면 표시 안 함 | 0 |
| `beats_per_measure` | 한 마디의 박 수 | 4 |

없는 키를 쓰면 오타를 조용히 넘기지 않고 줄 번호와 함께 에러를 낸다.

### 노트

한 줄에 노트 하나, 열은 최대 세 개다.

- **when** — 시간. 두 가지로 쓸 수 있다.
  - `2116` → 곡이 시작하고 2116 ms. **`lead_in` 은 빼고 센다**. 무음 구간 길이가
    바뀌어도 채보를 고칠 필요가 없다.
  - `4:1.5` → 4번째 마디의 1.5번째 박. 마디와 박 둘 다 1부터 세니까 `1:1` 이 곡의
    첫 박이다. `bpm` 과 `beats_per_measure` 로 ms 로 환산된다.
- **lanes** — `1` ~ `4`. 콤마로 이으면 동시치기다: `2,4`
- **hold** — 있으면 롱노트. `450` 은 밀리초, `1b` 는 한 박, `1.5b` 는 한 박 반.
  비우거나 `-` 를 쓰면 일반 노트.

`#` 뒤는 주석이고 빈 줄은 마음대로 넣어도 된다. 노트 순서는 상관없다 — 읽을 때
시간순으로 정렬한다.

### 도구

```bash
python make_chart.py song.mp3                      # song.dx 자동 생성
python make_chart.py song.mp3 -d hard --title "곡 이름" --level 9
python dx.py chart.dx                              # 문법 검사
python dx.py old_chart.json                        # 예전 json 채보를 .dx 로 변환
python check_sync.py chart.dx                      # 음원과 맞는지 측정
```
